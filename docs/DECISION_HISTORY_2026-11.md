## 2026-11-03

- **Automatic commit splitting has an explicit frozen switch.**
  `pipelines.plan-execution.automaticCommitSplitting` is a strict boolean that
  defaults to `true`, preserving size assessment for new commit-plan runs.
  `false` executes the predefined plan unchanged, skipping measurement,
  assessment calls and replacement proposals before any model call, while every
  ordinary gate still applies. It is a descriptor setting rather than a run
  option, so it uses the existing configuration precedence and adds no second
  override path. The existing size settings and their safe product stay
  validated while it is disabled, so re-enabling it cannot expose an invalid
  threshold. State version 39 freezes the switch in settings. The version-38
  migration derives it from saved eligibility rather than the new default, so
  historically ineligible runs stay ineligible and enabled runs keep every
  lineage, revision and consumed effect.

- **Global issue tracking is also available from the CLI.**
  `agent-run issues list`, `issues read`, and `issues update` are thin
  projections of the shared issue capability, so operators can triage the
  backlog without an MCP client while records, validation, conflicts, and
  retry identities stay identical to the MCP tools. Explicit `--clear-*` flags
  stand in for MCP's empty arrays and `null`, because an omitted flag must keep
  meaning "unchanged". The list filter is `--origin` rather than `--project`
  so the recorded path is never treated as a workspace that admission or Git
  would inspect. Deliberate creation stays MCP-only because it is reserved for
  a supervising client agent's explicit conclusion.

- **The global issue backlog is managed by revisioned MCP operations.**
  `issues_list`, `issues_read`, and `issues_update` read and update the shared
  store from any project, including after the origin is deleted and when
  deliberate capture is disabled, because tracking repaired or irrelevant
  issues must not depend on reporting new ones. Updates change only status,
  references, and the note, and require the inspected revision and document
  hash, so concurrent clients cannot silently overwrite each other. A narrow
  per-issue lease, not a worktree lease, serializes creation and updates so
  management never waits on unrelated runs; it lives in the shared store
  because clients with different state roots may share one store. Its per-revision hash ledger lets
  an interrupted update prove whether it was published even after a newer
  update, so exact retries return their receipt without replaying or
  overwriting newer metadata. Listing uses immutable creation-time/ID keyset
  cursors bound to the store and filters instead of an index file that would
  need its own consistency guarantees.

- **Deliberate issue reports move to one private per-user global store.**
  Repository-local reports required an ignored artifact directory and were lost
  with their checkout, and a global link to such a file would have kept that
  weakness. `unexpected_issue_report` now publishes `<issueId>.json` under the
  per-user data location (`$XDG_DATA_HOME/agent-runner/issues` on Linux), so
  publication needs no ignore rule and never writes to the project. Each
  document combines the immutable Markdown and its hash with one authoritative
  tracking record (origin, times, revision, finite status, optional references
  and note); a separate card file would have needed cross-file consistency.
  Completed receipts replay before origin or store resolution, so retries
  survive origin deletion. Intents bind the store path and directory identity,
  issue ID and document hash, so interrupted publication finishes in place and
  a moved or replaced store fails instead of redirecting. Compatibility with
  old local reports and the optional local issue index was deliberately not
  kept: they are neither discovered nor migrated, their files stay untouched,
  and an incomplete historical local publication fails explicitly.

- **Claude workspace-write commands reach the authorized launcher with an
  effective mount tree.** A workspace-write Worker could edit through native
  tools, but every sandboxed Bash workspace write returned `EROFS`: Claude
  ignored the spawning-parent `bwrapPath` because that tier did not take part
  in its policy, resolved `bwrap` through `PATH`, and applied the deliberate
  read-only preparation reservation itself. Turns now also put the launcher
  first on `PATH`, after pinning the real executable, and the fallback grammar
  accepts Claude's actual order: proxy-bridge binds and rewrites (made
  removals), private-tree mounts (discarded), outside masks, an empty

  earlier descendant mounts, so their restrictions are reapplied after it;
  ancestor pins come before every protection; immutability comes only from the

  earlier incremental design was rejected because it trusted mounts the grant
  had hidden and pinned an ancestor after a selected-file protection. Probes

  shell that runs only with a proof variable that Claude's credential denial
  removes in every sandbox and only the launcher restores. Readable managed
  files that select another bubblewrap make every access unavailable. Receipts

  remains unattributed.

- **Activity pages survive a proven concurrent publication.** MCP
  `run_activity` and `run_wait` readers failed with
  `Run changed during projection streaming.` (`ERR_INVALID_EVENT_LOG`) while
  the lease owner was healthy. A lock-free page drain requires stable handle
  and path observations of the active segment, and an ordinary owner append or
  rotation changes its size and timestamps. This is distinct from the
  historical unattributed SIGTERM 143. A drain failing with that code now
  reloads once through its original certificate, the same proof publication
  uses. It rereads exactly once only when every original binding, the namespace
  and the appended continuity are proven and the revision is strictly later;
  otherwise the original error is returned, and a second failure propagates.
  Widening the stat checks was rejected because size, mtime and ctime cannot
  distinguish an append from an in-place edit; only the digest-bound extension
  proof can. A blanket fallback around the extension was rejected because it
  hid unrelated failures: only `CheckpointInvalid`, now including a bound
  segment that is no longer safely openable, means unavailable proof, while
  skew, invalid or unsafe state, filesystem and programming errors propagate.
  The repair adds no sleep, polling or catch-all retry.

- **Codex local-commit refusals name their rule through `commit_failed`.**
  `ERR_CODEX_LOCAL_COMMIT_POLICY` used one class for a reported file change, a
  forbidden Git command and a missing or invalid readiness confirmation, and
  the pre-effect commit path then dropped even that class. The adapter now emits
  `operation_local_commit_file_change`, `operation_local_commit_git_operation`
  or `operation_local_commit_confirmation`. Plan execution persists the class
  beside an unproven pre-effect rejection and carries it into the retired
  `commit_failed` pause, its activity and its public explanation. The classes
  are distinct, bounded and redacted: no command, path, output or native
  message. A refused turn is not evidence that the policy is wrong; a reported
  run later completed with an ordinary retry, so the policy and one-shot commit
  authority are unchanged. Historical `operation_local_commit` records and
  class-free version-36 state remain valid.

- **MCP waits end when the execution owner is positively lost.** An owner can
  die without publishing a revision or touching its lease, so a held `run_wait`
  stayed open while a fresh `run_status` already reported `interrupted`. Waits
  now watch lease files and run a once-per-second read-only lease-owner probe
